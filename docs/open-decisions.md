# 기획에서 확정할 사항

상태: 아래 값은 모두 **미확정**이다. `img`에 등장하는 8,000걸음, 6,240걸음, 62P, 24종, 60P 등은 화면 예시로 취급한다. 오른쪽 제안은 다른 설계 문서에서 동작을 설명하기 위해 사용한 임시값이다.

## 먼저 결정할 항목

| ID | 결정할 질문 | 화면에 보이는 내용 | 임시 제안 / 결정 영향 |
| --- | --- | --- | --- |
| D01 | 로그인·계정 복구 방식은? | 로그인 화면 없음 | Firebase Auth 사용; 이메일·소셜·게스트 중 선택 필요. 계정 연결·복구와 친구 식별에 영향 |
| D02 | 최초 알은 어떻게 받고 활성 반려동물은 몇 마리인가? | 알과 홈 화면 | 최초 알 1개, 활성 개체 1개. 추가 알은 보유 목록에 두고 개체 전환 가능 |
| D03 | 걸음 목표는 얼마이며 변경할 수 있는가? | 하루 8,000걸음 예시 | 하루 8,000걸음 기본값, 일별 목표 스냅샷 저장. 개인 변경 허용 여부 결정 |
| D04 | 포인트 적립률과 일일 상한은? | 6,240걸음·+62P 예시 | 100걸음당 1P, 상한 없음. 예시와 맞춘 가정일 뿐 공식은 미확정 |
| D05 | 알 부화와 각 성장 단계의 기준은? | 알 부화 목표 8,000걸음 예시, 성장률 표시 | 알 부화 8,000걸음 예시, 이후 단계 기준과 돌봄의 반영 비율은 별도 확정 |
| D06 | 청혼 수락 시 새 알의 소유자는 누구이며 몇 개인가? | 두 친구를 닮은 새 알 | 두 사용자에게 각 1개씩 별도 지급. 한 개를 공동 보유하거나 한쪽만 받는 안과 결과가 다름 |
| D07 | 실제 출시할 범위와 일정은? | 8개 화면 | 모든 화면을 대상 기능으로 기록. MVP에 포함할 화면·기능은 팀에서 선택 |

## 걸음·성장 정책

| ID | 결정할 질문 | 임시 제안 / 영향 |
| --- | --- | --- |
| D08 | 측정 소스와 지원 기기·OS 버전은? | Android Health Connect, iOS HealthKit 제안. 기기별 사용 가능 여부와 출시 최소 버전 결정 |
| D09 | 걸음 동기화 시점·누락 보정 범위는? | 앱 실행·복귀 및 가능한 백그라운드 시점에 동기화; 가입일 포함 그 이후 날짜를 최대 7일 소급. 첫날 가입 전 걸음 포함 여부도 결정 |
| D10 | 기기 2대, 웨어러블과 기기 교체는? | 사용자당 대표 동기화 기기 1대, 플랫폼의 일별 합계 사용. 다른 기기 합산은 하지 않음 |
| D11 | 중복 전송과 원본 수치 감소·수정 시 보상은? | 일별 합계 최신값은 갱신, 이미 보상한 최대 걸음 기준으로 추가분만 지급. 수치가 줄어도 포인트·성장은 회수하지 않음 |
| D12 | 오프라인 중 발생한 걸음은 어느 개체에 반영하는가? | 동기화 시점의 활성 개체에 반영. 실제로 걸은 시점의 개체와 다를 수 있음 |
| D13 | 날짜·초기화 기준은? | 일자 집계는 `Asia/Seoul` 기준 자정. 해외 사용과 시간대 변경 정책 결정 |
| D14 | 상태별 초기값·최솟값·최댓값, 자연 감소와 행동 효과는? | 화면상 0~100% 형태. 행동별 증가량, 감소 주기·하한, 과잉 사용과 재사용 대기시간, 친구 방문 화면의 돌봄 점수 공식 결정 |
| D15 | 성장 기준에 걸음·먹이·놀이·행복·청결을 어떻게 반영하는가? | 임시 API는 걸음을 누적하고 단계 기준에 도달하면 전환. 돌봄 보너스의 공식과 기준별 버전 결정 |
| D16 | 한 개체의 생애 종료·방치·질병·수면 규칙은? | 화면에는 건강·약·재우기가 있으나 결과는 없음. 페널티와 회복 정책 결정 |
